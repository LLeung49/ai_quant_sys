# 板块异动使用指南

> 适用对象：`sector_rotation2.short_term`（模型版本 `v2_short_term`）。
>
> 定位：这是一个按交易日生成的板块 **1~2 日短期异动**研究工具；输出独立于 `v1` 主评分、阶段、Lifecycle 与排名，用于辅助板块轮动后续观察方向的研究筛选，不构成交易指令或收益承诺。

## 1. 已完成能力与使用边界

短期异动层与 `v1` 完全解耦，所有计算、存储、API 与前端展示均独立：

1. 从申万一级/二级行业日行情、个股复权日线和当前行业成分映射读取数据，与 `v1` 共用同一份原始行情。
2. 计算板块层与个股层短期原始特征：1/2/3 日收益与相对强度、当日量能脉冲、当日份额冲击、个股层面短期广度（5 日新高/站上 MA5 等）。
3. 沿用 `signed_percentile` 截面标准化合成 5 类短期评分（`pulse_score`、`volume_spike_score`、`breadth_spike_score`、`limit_score`、`momentum_shift_score`），输出 `short_term_composite` 与 `short_term_composite_rank`。
4. 应用 9 种异动标签（`pulse_up`、`pulse_down`、`extreme_up/down`、`volume_spike`、`limit_cluster/panic`、`short_rebound/breakdown_candidate`），并计算 `intense / moderate / mild / none` 强度分级；标签 **不引入迟滞**，但要求双证据最少命中。
5. 独立快照表 `sector_rotation_short_term_daily_snapshot`、独立 `config_hash`、独立 API 路由前缀 `/api/v1/sector-rotation/short-term`；与 `v1` 数据互不覆盖、不互相回填。
6. 提供单日可用日期、单日全板块快照、历史轨迹（最多 5 个板块）、异动榜（按标签+最低强度过滤）四个只读 API。
7. 前端在 `SectorRotationPage` 的"单日观察"模式嵌入 `ShortTermAnomalyModule`（2×2 KPI + 上下异动热力图），独立的 `ShortTermPage`（KPI + 异动榜 + 详情抽屉）作为可选入口；二者共用同一套数据与样式 token。

系统不做自动下单，不与 `v1` 主评分叠加、不读取 `v1` 阶段中间结果（`phase_age` / `velocity_score` 等）、不调权、不参与回测；所有阈值与权重集中放在 `ModelConfigShortTerm`，变更必须新建配置哈希并保留历史快照。

## 2. 每日结果应如何阅读

建议按以下顺序使用：

1. **先看 KPI 与运行元信息**：`pulse_up_count` / `volume_spike_count` / `limit_cluster_count` / `limit_panic_count` 反映当日短期异动密度；`eligible_sector_count` / `skipped_sector_count` 反映可参与评分板块的数量；`source_max_trade_date` 是上游行情实际截至日。
2. **再看异动榜与综合分**：短期榜按 `short_term_composite_rank` 升序排列，综合分是截面相对值，不是预期收益率。
3. **看标签命中**：每个板块可能命中 0~多个标签；标签按 `SHORT_TERM_LABEL_PRIORITY`（`pulse_up → pulse_down → extreme_up → extreme_down → limit_cluster → limit_panic → volume_spike → short_rebound_candidate → short_breakdown_candidate`）展示，靠前标签含义更强。
4. **用强度分级判断重要程度**：`intense > moderate > mild > none`；强度只是标签命中后的视觉分级，不参与计算。
5. **结合原始特征复核**：查看 `ret_1`、`rs_1`、`rvol_1_20`、`share_impulse_1d`、`breadth_up`、`limit_up/down_ratio`、`streak_*` 与 `short_term_composite`，避免被单一标签误导。

## 3. 数据、基准与质量规则

### 3.1 数据来源

| 数据 | 用途 |
| --- | --- |
| `trade_sector_daily` | 板块收盘指数、成交额、涨跌家数、涨跌停家数 |
| `trade_stock_daily_qfq` | 个股收盘价、成交额、最高/最低价；用于个股 RVOL、5 日新高、振幅等 |
| `trade_stock_status` | 当前申万一级/二级行业成分映射（与 `v1` 同口径，不引入历史映射修正） |
| `sector_rotation_run_log` | 复用 `v1` 审计表，仅追加 `model_version='v2_short_term'` 行 |
| `sector_rotation_short_term_daily_snapshot` | **新建**独立快照表，与 `v1` 快照分离 |

上游行情表仅读取。短期快照按模型版本与配置哈希保存，因此同一版本可以追溯和复现。

### 3.2 市场基准

- 与 `v1` 完全一致：基于校验后行业的归一化等权价格与成交额求和构建市场基准；
- 1 日与 2 日相对强度都使用该基准；不会因短期视角引入额外基准。

### 3.3 评分资格

- 横截面有效样本少于 `min_cross_section=20`（与 `rank_minimum_sectors` 同义）的指标不参与当日评分。
- 个股有效样本少于 `min_member_samples=5` 时，`breadth_*` 全部置空，对应标签不命中。
- `coverage_ratio < 0.80` 的板块 `score_eligible=false`（`coverage_ratio` 由调用方根据成员映射注入；当前骨架默认占位为 `NULL`）。
- 板块 `close_idx` 非正或当日缺失 → 该板块跳过；运行日志记录 `skip_reason=nonpositive_close`。
- `trade_stock_daily_qfq` 当日缺失 → 用最近有效交易日补齐（仅补 1 日），并在日志中标注 `patched_member_count`。
- `amount_t` 缺失 → `rvol_*`、`share_impulse_1d`、`amount_share_today` 全部置空。

### 3.4 主评分最低权重

`short_term_composite` 按 `score_weights`（`pulse 0.30 / volume_spike 0.20 / breadth_spike 0.20 / limit 0.15 / momentum_shift 0.15`）加权合成；当有效权重和小于 `score_minimum_weight=0.60` 时该板块不进入 `short_term_composite_rank`。

## 4. 原始量化指标/因子

所有时间窗口均为交易日。

### 4.1 板块层收益与相对强度

| 字段 | 公式 | 含义 |
| --- | --- | --- |
| `ret_1` | `P_t / P_(t-1) - 1` | 1 日绝对收益 |
| `ret_2` | `P_t / P_(t-2) - 1` | 2 日累计收益 |
| `ret_3` | `P_t / P_(t-3) - 1` | 3 日累计收益（保留以便研究） |
| `rs_1` | `ret_1 - 基准 ret_1` | 1 日相对强度 |
| `rs_2` | `ret_2 - 基准 ret_2` | 2 日累计相对强度 |
| `rs5_accel_1d` | `rs_5,t - rs_5,t-1` | 5 日相对强度的 1 日变化 |
| `ma5_slope` | `MA5_t - MA5_(t-1)` | 5 日均线日级斜率 |

### 4.2 量能与份额脉冲

| 字段 | 公式 | 含义 |
| --- | --- | --- |
| `rvol_1_20` | `当日成交 / MA20(成交)` | 当日量能相对 20 日均量 |
| `rvol_1_60` | `当日成交 / MA60(成交)` | 当日量能相对 60 日均量 |
| `amount_share_today` | `板块成交额 / 有效板块总成交额` | 当日成交额份额 |
| `share_impulse_1d` | `amount_share_t / amount_share_(t-1)` | 当日份额相对昨日的脉冲 |

### 4.3 个股层短期广度

| 字段 | 公式 | 含义 |
| --- | --- | --- |
| `breadth_up` | `rise / (rise + fall + flat)` | 当日上涨家数占比 |
| `breadth_above_ma5` | `close > MA5(close)` 个股占比 | 站上 5 日均线家数占比 |
| `breadth_new_high_5` | `close_t == max(high_{t-4:t})` 个股占比 | 5 日新高家数占比 |
| `breadth_strong_1d` | `ret_1 > 5%` 个股占比 | 单日强势股比例 |
| `breadth_weak_1d` | `ret_1 < -5%` 个股占比 | 单日弱势股比例 |
| `breadth_rvol_1d` | `amount_t / MA20(amount) > 1.5` 个股占比 | 当日放量家数占比 |
| `limit_up_ratio` | `limit_up / (rise + fall + flat)` | 涨停家数占比 |
| `limit_down_ratio` | `limit_down / (rise + fall + flat)` | 跌停家数占比 |

### 4.4 个股振幅与一致性

| 字段 | 公式 | 含义 |
| --- | --- | --- |
| `intraday_range` | `(high - low) / close` 的板块等权均值 | 个股日内振幅板块均值 |
| `ret_dispersion` | 个股 `ret_1` 横截面标准差 | 个股表现一致性；高分散 + 高涨幅表示"分化上涨" |

### 4.5 短期连续性（上限 5 日）

| 字段 | 公式 | 含义 |
| --- | --- | --- |
| `streak_pos_ret` | 连续 `ret_1 > 0` 的天数（最多 5） | 短期连续上涨天数 |
| `streak_high_breadth` | 连续 `breadth_up > 0.5` 的天数（最多 5） | 短期连续广度健康 |
| `streak_top_limit_up` | 连续 `limit_up >= 1` 的天数（最多 5） | 短期连续出现涨停 |

`streak_*` 上限为 5 是为了避免与 `v1` 的 5 日以上趋势信号语义重叠。

## 5. 短期评分与异动标签

### 5.1 短期评分族

| 评分 | 输入特征 | 含义 |
| --- | --- | --- |
| `pulse_score` | `rs_1`、`rs_2` | 短期相对强度脉冲 |
| `volume_spike_score` | `log(rvol_1_20)`、`log(share_impulse_1d)` | 当日量能脉冲（取对数减弱极端放量影响） |
| `breadth_spike_score` | `breadth_above_ma5`、`breadth_new_high_5`、`breadth_strong_1d`、`breadth_rvol_1d` | 短期广度脉冲（至少 2 项证据命中） |
| `limit_score` | `(limit_up_ratio - limit_down_ratio)` 截面归一化 | 涨跌停集群信号 |
| `momentum_shift_score` | `rs5_accel_1d`、`ma5_slope` | 短期趋势切换 |
| `short_term_composite` | 上述评分按权重合成 | 短期综合参考 |
| `short_term_composite_rank` | `score_eligible=true` 板块内的截面名次 | 与 `v1` 的 `composite_rank` 独立 |

评分族不进入 `v1` 主评分与 `composite_rank`；`score_eligible=true` 是进入异动榜与综合排名的前提。

### 5.2 短期异动标签（无迟滞，双证据命中）

| 标签 | 触发条件 | 语义 |
| --- | --- | --- |
| `pulse_up` | `rs_1 ≥ 0.005` 且 `breadth_up ≥ 0.55` | 单日强势脉冲上涨 |
| `pulse_down` | `rs_1 ≤ -0.005` 且 `breadth_up ≤ 0.45` | 单日强势脉冲下跌 |
| `extreme_up` | `ret_1 ≥ 0.03` | 单日极端上涨（≥+3%） |
| `extreme_down` | `ret_1 ≤ -0.03` | 单日极端下跌（≤-3%） |
| `volume_spike` | `rvol_1_20 ≥ 1.80` 或 `share_impulse_1d ≥ 1.30` | 当日显著放量 |
| `limit_cluster` | `limit_up ≥ 3` 且 `limit_down ≤ 1` | 涨停集群（情绪高涨） |
| `limit_panic` | `limit_down ≥ 3` 且 `limit_up ≤ 1` | 跌停集群（情绪恐慌） |
| `short_rebound_candidate` | `rs_1 ≥ 0.01` 且 `rs_5 < 0` | 短期反弹候选（前 5 日弱势中突然转强） |
| `short_breakdown_candidate` | `rs_1 ≤ -0.01` 且 `rs_5 > 0` | 短期走弱候选（前 5 日强势中突然转弱） |

阈值集中在 `ModelConfigShortTerm.thresholds`；调整任意阈值都会改变 `short_term_config_hash`，必须新建版本。

### 5.3 强度分级（仅作高亮，不影响计算）

| 强度 | 条件 |
| --- | --- |
| `intense` | 命中 `limit_cluster` / `limit_panic`，或 `pulse_score ≥ 0.75` 且 `volume_spike_score ≥ 0.50` |
| `moderate` | 仅命中 1 条主标签（含 `pulse_up/down`、`extreme_up/down`） |
| `mild` | 仅命中次级标签（`volume_spike`、`short_rebound_candidate`、`short_breakdown_candidate`） |
| `none` | 未命中任何标签 |

## 6. 与 `v1` 的解耦边界

| 维度 | `v1` | `v2_short_term` |
| --- | --- | --- |
| `model_version` | `v1` | `v2_short_term` |
| `config_hash` | `v1` 配置哈希 | 独立配置哈希，写入 `sector_rotation_run_log` |
| 快照表 | `sector_rotation_sector_daily_snapshot` | 新建 `sector_rotation_short_term_daily_snapshot` |
| 主评分 | `base_score`、`composite_score`、`composite_rank` | 不写入 `composite_rank`；提供 `short_term_composite_rank` |
| 阶段 | `phase_raw` / `phase_confirmed` / `phase_age` | **不读取不写入**；保留各自阶段逻辑 |
| Lifecycle | `lifecycle_state` 等 | **不读取不写入** |
| 市场状态 | `market_regime`、`regime_multiplier` | 不参与；前端可在 tooltip 单独说明 |
| 评分归一化 | `signed_percentile` | 复用 `signed_percentile`，权重独立 |
| API 路由前缀 | `/api/v1/sector-rotation` | `/api/v1/sector-rotation/short-term` |

**强约束**：`v2` 任何字段都不得反向回填到 `v1` 快照或读取 `v1` 阶段的中间结果。

## 7. 数据契约与存储

短期层使用独立快照表 `sector_rotation_short_term_daily_snapshot`，主键 `(as_of_date, sector_level, sector_name, model_version)`；审计沿用 `sector_rotation_run_log`，新增一行 `model_version='v2_short_term'`。任意字段重命名必须同步修改表结构（列顺序见 `snapshot_store.SHORT_TERM_SNAPSHOT_COLUMNS`）。

- `short_term_labels`：逗号分隔字符串，例如 `pulse_up,volume_spike`；解析与序列化由 Python 端负责。
- `short_term_intensity`：`ENUM('intense','moderate','mild','none')`，未命中任何标签时为 `none`。
- `coverage_ratio`：当前骨架默认 `NULL`，待成员映射注入；与 `v1` 同口径（`kline_stock_count / stock_count`）。
- `eligible_member_count` / `valid_member_count`：调用方按成员映射计算后挂回；写入策略与 `v1` 一致。
- `run_id`：与 `sector_rotation_run_log.run_id` 一一对应，运行失败时不会生成快照行，仅更新日志。

写入路径：`snapshot_store.persist_short_term_snapshot` 在事务内批量 upsert，任意一行失败整批回滚；运行审计由 `create_short_term_run` / `mark_short_term_run_succeeded` / `mark_short_term_run_failed` 维护。

## 8. 命令行与编程式入口

### 8.1 CLI（单日 / 回填）

```powershell
$env:PYTHONPATH = "src"
# 单日运行
python -m morning_conference.sector_rotation2.short_term.run_daily --level 2 --as-of-date 2026-08-08
# 回填区间
python -m morning_conference.sector_rotation2.short_term.run_daily --level 2 --backfill-start 2026-08-01 --backfill-end 2026-08-08
# 同时落盘 CSV（文件名 short_term_YYYYMMDD.csv）
python -m morning_conference.sector_rotation2.short_term.run_daily --level 2 --as-of-date 2026-08-08 --csv-output outputs/short_term
# 本地检视：只计算不写库
python -m morning_conference.sector_rotation2.short_term.run_daily --level 2 --as-of-date 2026-08-08 --dry-run --csv-output outputs/short_term
```

CLI 与 `v1` 同款；运行期会写入 `sector_rotation_run_log` 的 `running` 审计行，成功后置为 `succeeded`，失败置为 `failed`。

### 8.2 编程式入口

```python
from morning_conference.sector_rotation2.short_term import run_short_term_for, DEFAULT_SHORT_TERM_CONFIG

result = run_short_term_for(sector_level=2, as_of_date="2026-08-08")
print(result.eligible_sector_count, result.skipped_sector_count, result.snapshot_rows)
```

返回值 `ShortTermRunResult` 包含 `run_id` / `as_of_date` / `sector_level` / `model_version` / `config_hash` / `eligible_sector_count` / `skipped_sector_count` / `snapshot_rows`。

### 8.3 测试与回放辅助

- `calculate_stock_short_term_features(stock_history, config)`：在不依赖数据库的前提下计算个股层面短期指标，方便单元测试和回放；
- `classify_short_term_labels(row, config)`：纯函数标签判定，便于把历史快照数据再喂回去做回归测试。

## 9. API 接口

所有短期 API 路由前缀为 `/api/v1/sector-rotation/short-term`，仅暴露只读端点；如需触发每日运行，请直接调用 `run_short_term_for` 而非 HTTP。

### 9.1 可用日期

```
GET /api/v1/sector-rotation/short-term/available-dates
    ?level=1|2
    &model_version=v2_short_term
```

返回倒序排列的成功运行日期列表；前端用它作为日期选择器的下拉数据。

### 9.2 单日快照

```
GET /api/v1/sector-rotation/short-term/snapshot
    ?as_of_date=YYYY-MM-DD
    &level=1|2
    &model_version=v2_short_term
```

返回指定交易日的全板块短期异动快照；无成功运行时返回 `404 SHORT_TERM_SNAPSHOT_NOT_FOUND`。`meta` 字段附带 `source_max_trade_date`、`eligible_sector_count`、`skipped_sector_count` 和四个 KPI 计数（`pulse_up_count` / `volume_spike_count` / `limit_cluster_count` / `limit_panic_count`）。

### 9.3 历史轨迹

```
GET /api/v1/sector-rotation/short-term/history
    ?sector_names=...&sector_names=...
    &start_date=YYYY-MM-DD
    &end_date=YYYY-MM-DD
    &level=1|2
    &model_version=v2_short_term
```

最多查询 `MAX_SHORT_TERM_SECTORS=5` 个板块在闭区间内的每日短期异动轨迹；不返回 `phase_*` 与 `lifecycle_*`。

### 9.4 异动榜

```
GET /api/v1/sector-rotation/short-term/leaders
    ?as_of_date=YYYY-MM-DD
    &level=1|2
    &model_version=v2_short_term
    &labels=pulse_up&labels=volume_spike
    &min_intensity=moderate
```

`labels` 可多选，仅返回白名单内的标签（`pulse_up`、`pulse_down`、`volume_spike`、`limit_cluster`、`limit_panic`、`extreme_up`、`extreme_down`、`short_rebound_candidate`、`short_breakdown_candidate`）；`min_intensity` 取 `intense / moderate / mild`；返回按 `short_term_composite_rank` 升序的异动板块列表。

| `web/src/features/sector-rotation/short_term/nextDayWatch.ts` | 候选分组与排序纯函数：标签集合匹配 + 综合分 / 排名 / 行业名稳定排序 |
| `web/src/features/sector-rotation/short_term/labels.ts` | 标签与强度展示元数据（颜色 / 中文名 / 描述） |
| `web/src/features/sector-rotation/short_term/api.ts` | Zod 校验的只读 API 客户端，统一错误信封 |
| `web/src/styles/globals.css`（`short-term-*` 选择器） | 页面、工具栏、KPI、热力图、抽屉、Chip 等样式 |

`ShortTermAnomalyModule` 在 `SectorRotationPage` 的 `mode === "snapshot"` 时渲染，与主视图共享同一交易日与行业层级；`ShortTermPage` 是可选的独立入口，未默认挂到 `App` 顶层 Tab，可按需要接入。

### 10.2 工具栏

- **交易日选择**：默认使用 `availableDates` 的第一条（最近成功日期），可通过日期输入切换；切换时自动重拉快照。
- **行业层级切换**：`申万一级 / 申万二级` 分段控件，与 `SectorRotationPage` 同款。
- **标签筛选**：下拉框覆盖全部 9 种异动标签（`all` 默认显示所有命中板块）。
- **元信息**：`最近成功日期`、`上游行情截至`、`field_version=v2_short_term`，始终可见。

### 10.3 KPI

4 张图标卡：`单日脉冲上涨（pulse_up）` / `量能异动（volume_spike）` / `涨停集群（limit_cluster）` / `跌停集群（limit_panic）`，每张卡右上角有 `HintIcon` 说明口径；`row` 模式横向 1×4（独立页面），`grid` 模式 2×2（嵌入模块）。

### 10.4 异动榜与详情

- `ShortTermLeaders` 使用 ECharts treemap：单元面积映射 `|short_term_composite|`，颜色按 `ret_1` 正负渐变（红涨/绿跌），标签字体大小也随得分缩放；悬浮 tooltip 展示涨跌幅、异动分、强度、命中标签列表。
- 嵌入模块额外提供 `direction="up" / "down"` 两个热力图，分别展示上涨异动和下跌异动；独立页面只展示一个综合热力图。
- `ShortTermDetailDrawer` 展示：`short_term_composite` / `short_term_composite_rank` / `short_term_intensity` Chip + 命中标签 Chip + 收益与相对强度（`ret_1/2/3`、`rs_1/2`、`rs5_accel_1d`、`ma5_slope`）+ 个股层面广度（`breadth_up`、`breadth_above_ma5`、`breadth_new_high_5`、`breadth_strong_1d`、`breadth_weak_1d`、`breadth_rvol_1d`、`limit_up/down_ratio`）。`null` / `NaN` 显示"数据不足"。

### 10.5 标签与强度展示元数据

`SHORT_TERM_LABEL_META` 提供 9 种标签的颜色 / 中文名 / 描述；`INTENSITY_META` 提供 4 档强度（`intense` 橙红 / `moderate` 琥珀 / `mild` 蓝绿 / `none` 灰）。配色与 `v1` 主视图的阶段色刻意区分，且 `v2` 不复用，避免读者把"短期异动"误读为"阶段信号"。

### 10.6 次日研究观察候选面板

`NextDayWatchPanel` 在 KPI 之后、热力图之前插入 4 张固定顺序的研究情景卡，**基于完整 `snapshot.sectors`** 派生，与上方"标签筛选"互不影响。**严禁用于交易指令、仓位或收益判断**。

| 情景 ID | 展示名称 | 触发规则（标签精确匹配） | 研究解释 |
| --- | --- | --- | --- |
| `strength_follow_through` | 强势跟进观察 | 同时含 `pulse_up` 与 `volume_spike` | 当日相对强势和量能同步出现，次日重点复核延续性与广度 |
| `panic_reversal_watch` | 恐慌修复观察 | 同时含 `pulse_down` 与 `volume_spike`，或单独含 `limit_panic` | 下行压力或跌停集群已显化，次日重点复核恐慌是否扩散 / 收敛 |
| `short_rebound_watch` | V 形反弹观察 | 含 `short_rebound_candidate` | 前 5 日相对弱势后当日转强，次日重点复核反弹质量 |
| `short_breakdown_watch` | 破位警惕观察 | 含 `short_breakdown_candidate` | 前 5 日相对强势后当日转弱，次日重点复核风险是否延续 |

- **准入**：仅 `score_eligible=true` 的板块可入候选；同一板块允许多情景并存，不做互斥归类。
- **组内排序**：`short_term_composite` 降序 → `short_term_composite_rank` 升序 → 行业名 `localeCompare(zh-CN)` 升序；`null` / `NaN` 综合分稳定排在末尾。
- **展示**：每张卡默认显示前 5 条，超过 5 条显示"展开全部 N 个 / 收起"按钮；切换日期 / 层级 / 快照时通过 `useEffect` 自动收起，避免上一日交互状态带入新快照。
- **联动**：点击候选板块按钮调用 `ShortTermAnomalyModule.handleSelect`，与既有详情抽屉共享同一交互；上方"标签筛选"只影响下方热力图，候选面板始终反映当日完整有效快照。
- **元数据**：`NEXT_DAY_WATCH_GROUP_META` 在 `labels.ts` 内暴露中文标题、研究说明、帮助文案、配色基调与图标名；不含交易信号等级。
- **样式**：`.next-day-watch*` 作用域独立于 `.short-term-*`；桌面端 4 列、中等宽度 2 列、`≤760px` 单列。
- **单元测试**：`NextDayWatchPanel.test.tsx` 覆盖渲染、排序、展开 / 收起、点击回调、空态、快照切换重置；`nextDayWatch.test.ts` 覆盖纯函数规则与稳定排序；`ShortTermAnomalyModule.test.tsx` 新增集成测试验证候选面板与标签筛选互不影响。

## 11. 核心限制与风险

| 限制 | 事实与影响 |
| --- | --- |
| 标签不引入迟滞 | 与 `v1` 的 2 日迟滞形成对照，对单日噪声更敏感；阈值需保守，必要时用 `min_intensity=mild` 以上过滤 |
| 个股映射使用 `current_mapping` | 与 `v1` 同口径，存在历史回填偏差；本方案不进行成分历史修正 |
| 板块无 OHLC | 振幅 / 缺口类信号只能从个股聚合，与板块指数层面观察可能存在细微差异 |
| 不与 `v1` 主评分叠加 | 短期信号仅作"研究方向参考"，不能用于权重优化、组合构建或自动下单 |
| 不评估有效性 | 本方案不涉及 IC、Rank IC、分组收益、换手等指标；后续如需评估，必须用独立的样本外窗口（建议起步 1/2/3 日 horizon） |
| 与 Lifecycle 不联动 | `v2_short_term` 不会自动覆盖 `lifecycle_state`；如要联动，需另立规格 |
| `coverage_ratio` 占位 | 当前骨架默认写入 `NULL`，待调用方按成员映射注入；注入后即与 `v1` 同步口径 |
| 参数版本化但未跨阶段验证 | 所有阈值集中在 `ModelConfigShortTerm`，首次落地必须明确写出"v2_short_term 不进行 OOS 验证，仅做参数记录"的限制 |
| CSV 列顺序与 `coverage_ratio` 注入 | CSV 落盘时 `coverage_ratio` 为 `NULL`，需自行用成员映射补齐后再做研究 |

## 12. 后续迭代方向

后续工作应在独立模型版本和样本外验证后推进：

1. **接入板块日 K 线 OHLC**：从上游扩展 `trade_sector_daily` 或新增 `trade_sector_kline_daily`，允许缺口 / 振幅类信号从板块层面直采。
2. **板块分时数据接入**：若后续引入日内分时，可计算"午盘异动""尾盘异动"等更精细的短期信号。
3. **与 `v1` 联动观察工具**：在两套字段都齐全的前提下，提供"`v1` 阶段 + `v2` 短期异动"的并列视图，仅作研究展示，不参与评分。
4. **样本外验证**：当积累 6~12 个月短期快照后，可独立评估 `pulse_score`、`volume_spike_score` 等与 1/2 日前瞻收益的 IC 与分组表现。
5. **事件标注**：接入新闻、研报、政策事件流，作为"短期异动"的旁证；本期不接入。
6. **个性化过滤**：未来允许用户订阅"仅看 `pulse_up + volume_spike`"等组合；但本期只暴露预设筛选。
7. **数据血统披露**：所有异动榜单需显示数据截至时间、模型版本、配置哈希与"非投资建议"提示。
