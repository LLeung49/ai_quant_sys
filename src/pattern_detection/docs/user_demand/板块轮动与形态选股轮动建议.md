# 板块轮动与形态选股雷达联动分析

## 结论

建议采用“**板块决定研究方向，个股决定进入候选池**”的两层框架，而不是把全市场个股信号直接混排。

当前板块轮动模块提供行业的阶段、Lifecycle、综合排名等截面信息；`9-形态选股雷达.py` 提供个股的 MACD 底背离、看涨 K 线形态、量比和双重共振信号。两者可以按申万行业归属联动。

## 可复用的现有基础

- 板块轮动快照：`sector_rotation_sector_daily_snapshot`，包含行业阶段、Lifecycle、综合排名等。
- 行业归属：`sector_rotation2/data_loader.py` 已通过 `trade_stock_status.sector_1 / sector_2` 将股票映射到申万行业。
- 形态雷达：`9-形态选股雷达.py` 已扫描 MACD 底背离、10 类看涨 K 线形态、量比与双重共振。

## 联动链路

```text
板块轮动快照
  → 选出值得研究的申万行业
  → 取得该行业股票池
  → 行业内识别连板/龙头/强度结构
  → 对合格股票运行 K 线形态雷达
  → 输出“行业驱动的个股研究候选池”
```

## 阶段 × Lifecycle × 个股研究重点

| 板块阶段与 Lifecycle | 个股研究重点 | 当前形态雷达适配度 |
| --- | --- | --- |
| 修复确认 · 修复观察/初步启动 | 找底部修复、首次转强、放量反转 | 高：MACD 底背离与看涨形态适用 |
| 加速走强 · 初步启动/趋势运行 | 找行业龙头、连板核心、趋势延续 | 中：当前雷达偏底部反转，需补趋势形态 |
| 强势降温 · 趋势运行 | 找仍强于行业的核心股，防止追到后排 | 低：以持仓质量和强度筛选为主 |
| 强势降温 · 拥挤/背离 | 查风险扩散、龙头是否掉队 | 不应用看涨形态直接扩充候选 |
| 加速走弱 · 加速转弱 | 回避或观察风险 | 不进入新增候选池 |

当前形态雷达本质上是“底部反转雷达”，因此最适合服务于“弱势修复观察 / 修复确认”的行业；不能作为“加速走强”行业的主要选股工具。

## 建议输出的三类候选

| 候选类型 | 行业条件 | 个股条件 |
| --- | --- | --- |
| 修复型候选 | 修复确认或弱势修复观察；Lifecycle 为修复/初步启动 | MACD 底背离、看涨 K 线形态、量比放大 |
| 趋势龙头候选 | 加速走强或趋势运行 | 行业内相对强度靠前、成交额靠前、排名持续改善、连板或强势突破 |
| 风险观察名单 | 强势降温且拥挤/背离/转弱 | 龙头炸板、连板高度下降、相对强度掉队、放量滞涨 |

## 连板股识别

连板识别应独立于当前形态雷达，基于未复权日线计算：

- 前收价与涨跌停规则；
- 当日收盘是否封涨停；
- 连续涨停天数；
- 首板日期、最近涨停日期；
- 断板日期及断板后的表现。

输出字段至少包括：`limit_up_streak`、`first_limit_up_date`、`latest_limit_up_date`、`is_limit_up_today`、`broken_board_recently`。

## 行业内龙头识别

龙头不能只取涨幅最大股票。建议在每个申万行业内综合以下维度：

```text
龙头分数
= 35% 行业内相对收益
+ 25% 成交额/流动性地位
+ 20% 连板与涨停强度
+ 10% 技术形态信号
+ 10% 持续性与风险扣分
```

建议特征：

- 近 5/10/20 日相对行业收益；
- 行业内成交额及成交额占比；
- 连板高度、涨停次数、近期是否断板；
- 换手与量能；
- 形态雷达信号；
- 相对强度排名的持续性。

技术形态权重应按行业环境调整：

- 修复行业：提高 MACD 底背离、锤子线、看涨吞没、早晨之星等权重。
- 趋势行业：后续增加突破新高、均线多头、强势回踩、缩量回调后放量等形态。
- 风险行业：技术信号只用于评估反弹质量，不进入积极候选池。

## 前端接入建议

在板块详情抽屉的 Sector Insight 下增加“行业内个股雷达”：

- 龙头候选；
- 修复候选；
- 连板核心；
- 风险观察。

每只股票展示：连板数、行业内排名、形态、MACD 背离、量比、候选原因。

## 推荐开发顺序

1. 先做“行业 → 股票池 → 形态雷达结果”的联动候选表，只扫描板块轮动排名靠前且 Lifecycle 为修复/初启/趋势的行业。
2. 增加连板识别，输出连板高度、首板日期、是否断板、最近涨停日期。
3. 增加行业内龙头评分，输出每个行业 Top 3–5 的研究候选。
4. 最后接入前端，在行业抽屉呈现个股雷达。

## 代码结构建议

不建议持续向 `9-形态选股雷达.py` 追加板块、数据库和前端逻辑。应先将其中的 `scan_one`、`scan_bullish_patterns`、MACD 底背离计算抽取为可导入的纯模块；保留原脚本作为全市场命令行入口。

新的“行业联动雷达”调用纯函数，仅对板块候选行业的股票池进行定向扫描。这样可以避免板块逻辑、SQL 加载、CSV 输出和 TA-Lib 规则耦合在一个脚本中。
