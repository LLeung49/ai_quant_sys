# 板块轮动可视化设计规格 V1

## 1. 产品定位

本模块是量化研究网站中的“板块轮动”子页面，首批服务对象为**有一定投资基础的个人投资者**。它的目的不是给出交易指令，而是帮助用户理解：市场处于何种环境、今日哪些行业相对走强或走弱、这种变化是否正在加速，以及关注行业在最近一段时间如何轮动。

首版为无登录、只读页面；默认展示最新可用交易日，也支持查看已回填的历史日。页面使用深色、现代、专业的投研平台风格：高信息密度但层级清晰，结论先行，证据可展开。

### 1.1 产品边界

- 页面只消费 `sector_rotation2` 已落库且运行成功的日快照；浏览器不得直连 MySQL。
- 所有措辞使用“观察”“候选”“风险提示”“模型信号”，不得出现买入、卖出、收益承诺或个性化投资建议。
- 支持申万一级、二级行业切换，默认二级行业。
- 桌面端优先；移动端保留市场摘要、关注列表和单板块详情，不强制呈现完整高密度象限图。
- 本规格不含登录、自选、提醒、订阅、交易或下单能力，但 API 与组件边界需为这些能力预留扩展位。

## 2. 分期范围

| 版本 | 用户获得的能力 | 不包含的能力 |
| --- | --- | --- |
| V1-A：主视图 | 指定日期的市场摘要、象限气泡图、筛选/搜索、板块排名、单板块详情与指标解释 | 历史动画、账户功能 |
| V1-B：动态轮动 | 5/20/60 个交易日轨迹、最多三板块对比、全市场逐日回放、可拖动时间轴 | 个性化提醒、组合归因 |
| 后续 | 自选板块、变化提醒、组合持仓联动、主题/个股下钻 | 另立规格并设计权限与合规提示 |

V1-B 是 V1-A 完成后的紧接交付，不应作为遥远的“美化功能”。板块轮动的核心价值在于观察状态的连续变化，而非单日静态截面。

## 3. 信息架构与首屏

```text
顶部全局栏
  日期选择 | 行业层级（一级/二级） | 模型版本 | 市场状态 | 数据截至日期

市场摘要卡
  当前市场环境 | 可评分行业数 | 加速走强数 | 高风险/走弱数 | 数据覆盖提示

主工作区（桌面端）
  左：板块轮动象限气泡图                   右：今日关注列表
      X 轴：趋势速度/相对强弱                   排名、阶段、分数、日内排名变化
      Y 轴：趋势加速度                           搜索、阶段筛选、仅显示有效评分
      大小：量能活跃度
      颜色：确认阶段
      透明度：阶段置信度
      边框：参与度

板块详情抽屉（点击气泡或列表行后展开）
  结论摘要 | 评分拆解 | 指标证据 | 近期阶段变化 | 风险和数据口径
```

### 3.1 市场摘要卡

摘要卡必须让用户在不阅读图表前理解整体环境。

| 展示项 | 数据字段/计算 | 用户可见文案示例 |
| --- | --- | --- |
| 市场环境 | `market_regime` | `高波动：强势信号需降低确定性预期` |
| 风险乘数 | `regime_multiplier` | 仅在“查看方法说明”中展示数值，不作为投资建议 |
| 可评分行业数 | `score_eligible=true` 的数量 | `113 个行业具备完整评分证据` |
| 加速走强数 | `phase_confirmed=accel_up` 的数量 | `8 个行业处于加速走强阶段` |
| 风险/走弱数 | `accel_down`、`decel_up` 等按产品文案分组 | `14 个行业出现趋势降温或走弱迹象` |
| 数据覆盖告警 | `coverage_ratio`、运行审计状态 | `部分行业覆盖不足，未参与今日排名` |

## 4. 象限气泡图设计

### 4.1 视觉编码

| 图形属性 | 字段 | 业务含义 | 交互规则 |
| --- | --- | --- | --- |
| X 轴 | `velocity_score` | 相对市场的趋势速度 | 数值范围固定为 `[-1, 1]`，零轴为相对中性 |
| Y 轴 | `acceleration_score` | 趋势变化的加速/减速 | 数值范围固定为 `[-1, 1]`，零轴为变化拐点 |
| 气泡面积 | `volume_score` | 成交/资金活跃度的截面相对位置 | 缺失时使用最小中性气泡并在提示中说明 |
| 填充色 | `phase_confirmed` | 已确认的轮动阶段 | 颜色不可单独被理解为涨跌幅 |
| 透明度 | `phase_confidence` | 阶段判断的证据强度 | 最低透明度设下限，避免不可见 |
| 描边宽度/亮度 | `participation_score` | 行业内部参与度 | 强参与度显示更清晰描边 |

阶段颜色采用低饱和、色盲友好的组合，同时始终配合文字标签，不能只靠颜色传达信息：

| 阶段 | 默认文案 | 颜色语义 |
| --- | --- | --- |
| `accel_up` | 加速走强 | 青绿色 |
| `decel_up` | 强势降温 | 琥珀色 |
| `bottoming_candidate` | 弱势修复观察 | 蓝紫色 |
| `accel_down` | 加速走弱 | 珊瑚红 |
| `neutral` | 方向未明 | 中性灰 |

实际中文文案须通过一个集中映射表维护；不得在图表、列表与详情中分别硬编码。

### 4.2 象限解释

页面必须在图表边缘给出简短解释，降低量化术语门槛：

```text
左上：修复/弱转强观察       右上：加速走强
左下：加速走弱               右下：强势降温
```

该解释是阅读辅助，不替代 `phase_confirmed` 的规则。`phase_confirmed` 仍由迟滞和历史确认生成，不能仅根据气泡当前所在象限前端重算。

### 4.3 Tooltip 与选择行为

悬浮提示至少显示：行业名称、综合排名、`composite_score`、当前阶段及置信度、速度、加速度、量能、参与度、排名 1/5 日变化和覆盖率。数字需同时提供“相对截面得分”解释，避免用户把 `[-1,1]` 误读为收益率。

点击气泡或右侧列表中的行业后：

1. 高亮该气泡、弱化其余气泡；
2. 打开下方/右侧详情抽屉；
3. 在 URL 查询参数中保留行业、日期和层级，支持刷新与分享；
4. 移动端改为全屏详情页，并保留返回入口。

## 5. 今日关注列表与详情抽屉

### 5.1 关注列表

默认排序为 `composite_rank` 升序，只展示 `score_eligible=true` 的行业；用户可切换“排名上升最多”“加速走强”“强势降温”“加速走弱”排序/筛选。列表行包含：排名、行业名称、阶段标签、综合评分、1 日排名变化、置信度。

没有评分资格的行业不可混入排名，但可通过“数据覆盖”筛选查看，明确显示未参与排名的原因。

### 5.2 单板块详情

详情区按如下顺序呈现：

1. **一句话结论**：例如“相对强势仍在，但加速度转弱，需关注是否继续降温。”
2. **状态证据**：阶段、持续天数 `phase_age`、置信度 `phase_confidence`、市场环境。
3. **评分拆解**：趋势位置、速度、加速度、参与度、量能分数，配合“高于/低于当日行业中位数”的语言。
4. **原始特征**：RS、均线距离、RVOL、广度、覆盖率等；默认折叠。
5. **排名变化**：`composite_rank`、`rank_change_1d`、`rank_change_5d`、`top10_days_20`。
6. **口径与风险**：模型版本、成员映射口径、覆盖不足提示和“非投资建议”。

结论文案必须基于确定的字段映射与模板生成，不能由前端擅自将高分翻译为确定性收益预期。

## 6. 动态轮动视图（V1-B）

### 6.1 单板块轨迹

用户选择一个行业后，可切换 `5 / 20 / 60` 个交易日窗口，默认 `20`。轨迹节点使用同一坐标系：每个交易日的 `(velocity_score, acceleration_score)`；线条从旧到新渐变，最新节点更亮并带日期标签。

轨迹只查询已成功入库的连续交易日。若时间窗口中存在未回填或失败日期：

- 断开轨迹，不使用直线跨越缺口；
- 显示缺口日期和原因；
- 不以插值伪造历史位置。

最多允许同时选择三个行业，图例可单独隐藏/显示，以保证可读性。

### 6.2 全市场回放

全市场回放复用主图的视觉编码，增加日期范围、播放/暂停、上一步/下一步、速度选择和可拖动时间轴。播放仅改变已加载快照的显示日期，不在播放过程中反复请求接口。

首次实现采用逐日切换动画；不在 V1-B 中实现预测轨迹、平滑插值或实时流数据。

## 7. 前后端架构和数据契约

### 7.1 工程边界

在当前仓库新增独立 `web/` 子工程：React、TypeScript、Vite、Apache ECharts、TanStack Query、Tailwind CSS 与 shadcn/ui。Python 端新增只读 HTTP API 层，读取现有派生表；浏览器通过 HTTPS 请求 API，不能访问数据库凭据或直接查询 MySQL。

```text
React 浏览器页面
  -> /api/v1/sector-rotation/* （只读 API）
  -> sector_rotation_sector_daily_snapshot / sector_rotation_run_log
  -> MySQL
```

### 7.2 最小 API

| 端点 | 目的 | 关键参数 |
| --- | --- | --- |
| `GET /api/v1/sector-rotation/available-dates` | 返回具有成功运行记录的可用日期 | `level`, `model_version` |
| `GET /api/v1/sector-rotation/snapshot` | 主视图单日完整截面 | `as_of_date`, `level`, `model_version` |
| `GET /api/v1/sector-rotation/sector-history` | 一个或多个行业的历史轨迹 | `sector_names`, `start_date`, `end_date`, `level`, `model_version` |
| `GET /api/v1/sector-rotation/replay` | 指定日期范围的市场回放数据 | `start_date`, `end_date`, `level`, `model_version` |

所有响应必须含 `as_of_date`、`sector_level`、`model_version`、`source_max_trade_date`（若可取得）、运行状态和字段版本；API 只返回 `status=succeeded` 的快照。空数据、参数非法、日期未回填和数据库失败要返回不同、可读的错误码。

### 7.3 主视图响应形状

```json
{
  "meta": {
    "as_of_date": "2026-08-04",
    "sector_level": 2,
    "model_version": "v1",
    "market_regime": "high_volatility",
    "regime_multiplier": 0.85,
    "eligible_sector_count": 113
  },
  "sectors": [
    {
      "sector_name": "示例行业",
      "score_eligible": true,
      "velocity_score": 0.42,
      "acceleration_score": 0.31,
      "volume_score": 0.18,
      "participation_score": 0.55,
      "phase_confirmed": "accel_up",
      "phase_confidence": 0.71,
```

数值缺失使用 JSON `null`，不能使用字符串 `"NaN"`、`"None"` 或伪造零值。前端收到 `null` 必须展示“数据不足”，而不是把行业放到坐标原点。

## 8. 性能、质量与验收

- 单日二级行业主视图的 API 响应目标小于 500 KB；前端首屏在普通宽带下可交互时间目标小于 3 秒。
- 轨迹接口只返回选定行业和日期范围需要的字段；回放接口可按日期分页或压缩，但不得一次无界返回全历史。
- 图表、筛选、列表和详情必须复用同一份查询结果与字段映射，不允许各自调用不同接口造成口径不一致。
- 所有颜色均有文本标签和 tooltip 作为非颜色替代信息；键盘可操作日期、筛选与列表。
- 空状态需明确区分“该日期尚未回填”“运行失败”“无符合筛选的行业”“行业数据覆盖不足”。
- 每个 API 的 SQL 查询须参数化，并限制可接受的行业层级、模型版本、日期范围和行业数量。

## 9. 开发前置条件

1. 至少完成一级、二级行业相同模型版本的连续日快照回填；动态轨迹的 60 日窗口需要至少 60 个成功交易日。
2. 先确认 Python Web 框架选型（建议 FastAPI）及整体网站未来是否由同一服务提供 API。
3. 在前端开始前，补充 API 字段字典和中文文案映射的自动化测试。
4. 完成 V1-A 的可点击原型评审后，再搭建前端工程；不得直接以静态 HTML 或图片替代正式交互图表。
