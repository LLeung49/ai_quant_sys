# 防御层与宽基 Beta 层 GRID/TREND 风险调整后研究设计

**日期：** 2026-09-10
**状态：** 已确认，待编写实施计划
**范围：** `src/asset_allocation/etf_adaptive` 的研究、验证报告和人工实盘操作单准入

## 1. 背景与目标

防御底仓层与宽基 Beta 层已经采用 GRID/TREND 自适应交易框架。当前研究显示，部分代表性 ETF 的策略回撤较低，但相对买入并持有（B&H）存在收益不足，归因显示止损、冷却期和趋势退出后空仓可能错失上涨。

本轮不替换 GRID/TREND 的交易结构，也不以单一收益或单一综合分数决定去留。目标是在严格的样本外（OOS）研究下，找到稳健、可解释且可执行的参数区域，并形成可审计的风险调整后结论：继续优化、通过实盘准入、需要评估结构调整或不纳入实盘。

策略结构改变（例如长期核心仓 + 交易卫星仓）不属于本轮实现范围；只有报告证据证明现有结构在多资产、多 OOS 窗口中系统性失效时，才作为待用户确认的后续方案提出。

## 2. 不变约束

- 研究对象限于防御层与宽基 Beta 层的代表性 ETF，以及后续具备 PIT 成分证据的蓝筹股；不做全市场 ETF 产品的组合寻优。
- 策略入场、网格加减仓、趋势加仓的既有业务结构不改变。
- 任何参数选择只能使用训练窗口；随后 OOS 窗口不得回流用于选参。
- 数据完整性、raw/qfq 正向仿射一致性、无未来函数和研究证据完整性是硬前置条件。
- 仅生成供人工确认的操作建议；系统不得自动向券商下单。

## 3. 决策模型：三道门与结论分类

不使用可任意调权的单一总分。每个标的、子组合及层级组合相对其 B&H 基准经过以下三道门。

### 3.1 研究有效性门

必须满足：

1. 行情数据完整、时间对齐且 raw/qfq 仿射一致性审计通过；
2. 每一个研究窗口均可重现其数据版本、配置哈希与训练/OOS 边界；
3. 选参过程没有使用 OOS 数据；
4. 正式结论要求足够数量的 OOS 窗口；短历史标的仅作参考性证据，不能单独放行层级实盘；
5. 推荐参数须存在稳定邻域，而非仅一个尖峰最优点。

任何一项失败均为研究无效：报告可保留诊断，但不得产生“通过”或操作单。

### 3.2 风险调整后表现门

策略与 B&H 必须并列呈现以下指标及 OOS 分布：

- 年化收益、年化波动率和最大回撤；
- 夏普比率、索提诺比率、卡玛比率；
- CVaR(5%)、最差滚动 126 个交易日收益、回撤修复期；
- OOS 非落后窗口比例、最差窗口与窗口间离散度。

用户偏好为风险调整后收益优先：若策略年化收益略低于 B&H，但最大回撤、CVaR、修复期以及夏普/索提诺/卡玛有实质、稳定改善，不能机械淘汰；其状态应由下述分类结合可执行性决定。

### 3.3 可执行性门

报告须说明结果的实现代价与市场暴露：

- 换手率、交易次数、交易成本；
- 持仓/空仓交易日、平均有效仓位；
- 网格初始化、网格止损、冷却、趋势入场、加仓和趋势退出对盈亏、回撤及错失行情的归因。

低回撤若主要来自长期空仓，不可被误判为改善；它必须在收益、尾部风险和暴露归因中被明确揭示。

### 3.4 结论状态

| 状态 | 含义 |
| --- | --- |
| `passed` | 研究有效性与可执行性达标，且风险调整后表现相对 B&H 整体占优或满足明确的防御性改善要求。 |
| `continue_parameter_optimization` | 风险或尾部指标有可重复改善，但收益/风险调整指标仍未达标，且归因能指向少量可控参数。 |
| `evaluate_structural_change` | 多资产、多 OOS 窗口下，现有参数稳定区域均在收益及风险调整指标上持续落后；仅提出结构变体建议，不实施。 |
| `do_not_trade` | 数据、研究、执行前提或结果不支持实盘。 |

## 4. 受控参数优化

本轮只扩展已被归因直接指向的退出与过滤参数；保留既有网格间距、单位仓位、初始仓位、趋势风险比例、趋势加仓间距和最大加仓次数的搜索能力。

新增纳入参数空间的字段：

| 模块 | 参数 | 研究问题 |
| --- | --- | --- |
| 网格 | `atr_stop_multiple` | 网格止损是否过紧，导致趋势行情中提前退出。 |
| 网格 | `cooldown_sessions` | 冷却期是否造成过长空仓。 |
| 趋势 | `stop_n` | 趋势退出容忍度是否不足。 |
| 趋势 | `require_macd_bullish` | MACD 过滤是否错过了可接受的再入场。 |

每个候选配置的流程为：在训练窗口选参；在紧随其后的独立 OOS 窗口完整执行；聚合所有 OOS 窗口；检查参数邻域。报告输出推荐的参数区间和一个可复现的默认配置，而不是宣称唯一最优点。

若受控扩展后仍无稳定改善，研究引擎须生成 `evaluate_structural_change` 证据包，说明失败在哪些资产、窗口和指标上；不得把未批准的新结构混入参数优化。

## 5. 研究产物与数据流

研究结果按“单标的 → 子组合 → 层级组合”逐层生成。每层保留输入成员、权重、基准、数据审计、参数配置、训练/OOS 时间边界和运行环境信息。

每次运行落盘以下产物：

1. 机器可读 JSON：完整指标、结论、证据、数据审计、参数与配置哈希；
2. CSV：逐 OOS 窗口指标、逐笔交易、逐日权益/暴露；
3. Markdown：面向决策者的摘要、基准对照、证据链、风险说明及下一步建议；
4. 图表：权益与回撤、策略/B&H 对比、买卖点、仓位/空仓暴露、按事件的归因图；
5. 研究运行清单：代码版本、运行时间、数据截止日、输入 Universe 版本。

报告的“决策摘要”须首先显示：研究状态、是否可生成操作单、相对 B&H 的核心指标、最关键的归因、以及“继续优化参数 / 评估结构调整 / 不纳入实盘”的原因。

## 6. 实盘操作单准入

操作单是人工下单建议，不具备自动交易权限。生成前必须同时满足：

1. 所属层级组合的正式研究状态为 `passed`；
2. 当日数据审计通过；
3. 当日运行配置哈希与已批准研究配置相同；
4. 操作单输入的成员、权重、基准和数据截止日与批准研究一致；
5. 没有未处理的数据异常、研究证据缺失或风控拦截。

任一条件不满足时，仅生成风险提示与原因，不产生可执行交易指令。

## 7. 错误处理

- 数据异常、缺失窗口、仿射校验失败或无法建立 B&H 基准：失败关闭，状态为 `do_not_trade`。
- 训练/OOS 边界、参数哈希或成员版本不完整：报告标记研究无效，禁止层级放行。
- 不能计算某项指标：保存明确的缺失原因，不用零值替代；结论不因缺失字段被抬高。
- 短历史标的：保留参考报告，标明窗口不足，不能成为唯一的层级放行证据。

## 8. 验收与测试

实现必须覆盖以下自动化测试：

1. 全部新增指标的确定性计算和策略/B&H 并列输出；
2. 训练/OOS 隔离：验证数据变化不得改变训练期候选选择；
3. 参数邻域稳定性：尖峰候选不能被推荐为默认配置；
4. 四类结论状态在数据无效、可优化、结构性失败和通过场景下的分类；
5. 报告 JSON/CSV/Markdown/图表的字段与可复现性；
6. 买卖点、空仓暴露和事件归因的一致性；
7. 操作单在任一准入条件不成立时必须拦截；
8. 既有 raw/qfq 仿射一致性与研究回归测试不得退化。

## 9. 非目标

- 本轮不新增全市场 ETF 筛选或组合最优化器。
- 本轮不替代用户已认可的 GRID/TREND 策略框架。
- 本轮不实现自动券商下单。
- 本轮不以没有 PIT 成分证据的蓝筹历史股票池形成正式防御层放行结论。
