# 板块轮动交易日历设计

日期：2026-08-12

## 目标

用交易日历替代当前仅列出成功快照日的下拉框。用户能看见最近交易日中哪些已有板块轮动快照，并能选择尚未生成快照的交易日获得明确提示，而不是被静默回退。

## 范围

- 支持一级、二级行业与指定模型版本的日历可用性状态。
- 默认展示包含最新上游交易日的月份，可翻阅相邻月份。
- 日历日期分为三类：
  - 有成功快照：正常高亮，可选择并加载该日快照。
  - 交易日但无成功快照：灰色但可点击；点击后显示“该交易日的板块轮动快照尚未生成”。
  - 非交易日：禁用、不可点击。
- 选择无快照交易日不发起必然失败的快照请求，保留最后成功快照的内容；界面明确显示“当前查看数据”为该快照日期及“所选日期无快照”的提示。
- URL 中的 `date` 保留用户所选交易日；刷新后仍可看到提示与最后成功快照。

## 数据与接口

新增只读日历可用性接口，输入 `level`、`model_version` 及可选月份范围，输出：

- `trade_dates`：上游 `trade_sector_daily` 对应层级的交易日；
- `snapshot_dates`：该层级、模型版本下状态为 `succeeded` 的快照日；
- `latest_snapshot_date`：最近成功快照日。

服务端负责获取交易日，不让前端通过周末或自然日规则推断节假日。查询必须限制月份范围并参数化。

## 前端状态与交互

新增 `TradingCalendar` 受控组件，接收交易日、快照日、选中日期和回调。组件只负责呈现与选择，不发请求。

页面状态区分：

- `selectedDate`：用户选择/URL 指定的交易日；
- `loadedSnapshotDate`：用于请求及呈现的最近成功快照日。

当 `selectedDate` 没有快照时，`loadedSnapshotDate` 为不晚于该日的最近成功快照；当没有任何历史成功快照时，显示空状态。该规则避免未来日期错误展示，也避免请求 404。

## 错误处理

- 日历元数据请求失败：显示与当前快照请求相同的可重试错误态。
- 无快照交易日：这是预期业务状态，使用提示条，不显示 API 故障。
- 非交易日：不可点击，不产生状态或网络请求。

## 验收与测试

- API：返回交易日、成功快照日及最新快照日，并按日期格式与边界校验。
- 日历：有快照日可选；无快照交易日灰色但可选并回调；非交易日禁用。
- 页面：选择或 URL 指向无快照交易日时保留该日期、显示业务提示、使用最近成功快照；不会调用该无快照日的 snapshot API。
- 回归：现有日期切换、回放、行业层级切换及 URL 序列化测试保持通过。

## 非目标

- 不自动触发 `run_daily`。
- 不提供实盘交易日历或法定节假日的独立维护表。
- 不改变 P1/P2 研究计算逻辑。
