# 财务 PIT 迁移、历史回补与验收设计

日期：2026-10-20。范围仅涵盖财务报表、股本、依赖财务的 Repair Alpha/估值和日常财务采集。已验收的行情与非财务 Web 日常任务保持独立。

## 用户目标与约束

- 2015-01-01 起的 QMT 财务缓存正在下载。本周仍可使用 QMT HTTP 桥接读取；下周起按本地文件导入，不再依赖桥接服务。
- 正常且经过数值核验的历史 QMT 数据可以作为数值基准；历史时点可见性须另外取得同版本的披露/修订证据。QMT 数值缺失或不合格时使用 AKShare 补齐；以后日常新增财务数据由 AKShare 采集。
- EPS、ROE 等指标重要，应保留可用日期、来源、计算口径，进入 PIT 体系；没有披露时间证据的宽表值不可冒充历史时点可用值。
- 不运行旧 QMT/miniQMT 财务脚本直写正式表，不重写原始来源标记，不为弥补空值写入零。

## 已核实基线

2026-10-20 只读数据库审计：`trade_stock_financial` 有 QMT 166,904 行、AKShare 507 行；`trade_stock_financial_raw_pit` 有 QMT 166,973 行标记 `EXACT`、1 行 `pit_estimated`，AKShare 507 行 `pit_exact`；`trade_stock_capital_pit` 为空。QMT PIT 的 166,781 行与同来源宽表的五个核心字段完全匹配，另 193 行未匹配；AKShare 的 507 行全部匹配。进一步全表核对发现：**166,973 条 QMT `EXACT` 行的 `announcement_date` 全部等于 `report_date`**，`source_table` 均标为 `trade_stock_financial`；这不是经证实的历史公告日，存量 `EXACT`、`source_verified=1` 标记不能作为历史可见性证据。具体写入程序尚未追溯到，宽表衍生来源是根据行元数据作出的判断。507 条 AKShare 行的公告/更新日可追溯到当前采集器使用的 Eastmoney `NOTICE_DATE`/`UPDATE_DATE`；唯一 miniQMT 行的公告日为空。

旧 `data_ingestion_qmt/2-财务数据采集_qmt_bridge.py` 从 QMT 财务报表及 `PershareIndex` 取 EPS、ROE、毛利率，部分指标再计算；其 PIT 双写路径写 `announcement_date=NULL` 和 `pit_estimated`。当前 AKShare 采集器把 EPS 取自利润表，其余六个比率由财报字段计算，但仅把五个核心字段写入 PIT，并会对宽表执行 upsert。Repair Alpha 直接读取 PIT 和股本 PIT；其 PIT 读取端目前没有来源优先级。旧宽表并非现有 Repair Alpha 的直接输入。

现有 `QMTDataGateway.get_financial_data` 调用 `/api/data/raw_financial_data`，映射 Balance、Income、CashFlow、PershareIndex 和 Capital，但输出的 `m_timetag` 是报表期索引，字段清单不含公告日或修订时间；Capital 映射只有 `total_capital`。所以该接口可用于数值/总股本归档，**不能单独产生历史 `pit_exact`**，也不能证明流通股本。若存量 QMT PIT 的公告日来自另一套证据，需逐样本找到并核对来源；否则严格历史计算使用有独立披露证据的版本，桥接所得指标最早以本次捕获日可用。该限制不否定 QMT 数值可用于当前数据补齐。

补充发现：本机安装的 `xtquant.xtdata.get_financial_data_ori` 可直接返回底层原始记录，财报字段配置包含 `m_anntime`（披露时间）。普通 `get_financial_data` 封装在 `m_anntime` 为 NaN 时会用 `m_timetag` 回填，因此它的非空公告日也不自动构成证据。客户端数据服务当前未连通，尚未实查下载缓存中 `m_anntime` 的覆盖率和修订版本；应优先从原始接口或经过样本验证的原生文件读取字段及缺失状态，与数值一起归档，再做逐版本核验。旧桥接遗漏时间字段，不代表 QMT 缓存必然没有时间字段。

2026-10-20 离线只读探查已为 QMT 原生缓存的 42,167 个 `.DAT` 文件生成 SHA-256 清单，共 3,143,311,096 字节。四类财报文件（`7001/7002/7003/7008`）按统一记录长度及样本中的报告期/披露日位置试读，共 957,354 条记录，均读到晚于报告期的候选披露时间；同文件内报告期重复的记录共 160,679 条，提示修订版本。样本 `600000.SH` 的 2015Q1 显示 2015-03-31/2015-04-30。该二进制解析只是**临时探查证据**：表类型、字段偏移、时间语义及数值版本仍需以原始接口/配置及跨来源样本核验，未达到正式 PIT 发布条件。30 条近期 AKShare 记录中有 21 条的可用日期能在对应 QMT 文件找到，另 9 条不相同，进一步说明不能直接跨来源按报告期套日期。

## 方案选择

1. 全量 AKShare 重刷：来源单一，但要重新抓取 5,000 多家公司十余年财报，成本和网络失败风险高，也会丢弃可用 QMT 历史。
2. 延续 QMT 单一路径：本周吞吐较好，但桥接即将停用，日常更新无法持续。
3. **采用混合迁移**：QMT 负责已核验历史数值和本周缓存补齐；披露时间由 QMT 原生文件中经验证的字段或独立公告证据补足。AKShare 负责缺口与今后增量。来源选择在读取层按版本和历史可用日期明确执行，写入层不靠覆盖宽表表达优先级。

## 长期数据模型

`trade_stock_financial_raw_pit` 是财务报表的事实表，按股票、来源表、报告期和内容哈希保留版本。扩展 EPS、ROE、ROA、毛利率、净利率、资产负债率、流动比率，以及可取得的计算输入（营业成本、负债合计、流动资产、流动负债）。每个版本保留报告期、首次公告日、版本实际可用日、首次采集日、来源、哈希、字段来源/公式及质量状态。只有可追溯到原始披露证据的 `announcement_date` 才能作为版本可用日；现存 QMT `EXACT` 行的报告期复制日期必须先隔离或纠正。若原始公告日与更新日不同，另存原始公告日。新字段均允许 `NULL`，缺失不得填零。金额单位为元，比率列沿用宽表的百分数口径（流动比率为倍数），EPS 为元/股；股本为股。

`trade_stock_capital_pit` 单独保留。股本变更与季度报表不具有同一报告粒度，按变更日、公告日和来源版本选择。它的空表状态是 Repair Alpha 市值和估值验收的独立阻塞项。

`trade_stock_financial` 暂作为兼容与核对表保留，不作为严格历史研究输入。PIT 及依赖方验收后停止双写；只有确认 EPS 等字段和外部消费者均可迁移后才归档宽表，不在本次回补开始时删除。

## 采集、文件与发布流程

桥接读取器只读 QMT，不连接正式表写入口。本周将已下载缓存批量抽取为带 `batch_id`、股票、原始表名、原始字段、原始公告/更新字段、提取时间、文件哈希的归档。归档使用有版本的 JSONL/manifest 契约，以便桥接结束后可离线重放。文件导入器读取同一契约；对于 QMT 客户端原生文件，先识别实际格式并转换为该契约，原始字节和校验和保留。未知文件格式不得猜测字段或日期；应在拿到样本后以可复现解析器及样本测试接入。

当前桥接没有的公告/更新字段在归档中明确为 `null`；原始 QMT `m_anntime` 若可取得，应同时保留原始值、缺失状态和版本证据，不能使用普通封装的 `m_timetag` 回退值或本次下载时间冒充公告日。股本 `total_capital` 先确认单位及对应变动/公告日期；无日期证据时可以暂存作当前参考，不能发布为历史股本 PIT。需要流通股本时由具备披露日期的其他来源补齐或记录缺口。

桥接归档、文件导入和 AKShare 响应统一进入隔离暂存，再使用同一规范化和发布器。每批记录总数、成功/失败股票、覆盖报告期、字段空值、公告日证据、去重/冲突和异常原因。失败批次允许重跑；同 `batch_id` 与内容哈希重复导入应幂等，哈希变化必须生成新版本。不得将“接口成功但空响应”当作该股票全部历史无财报。

日常 AKShare 增量从首次观察开始，先归档每次响应的原始字段、公告日、更新日、抓取时间和内容哈希，再按版本发布。公告日与更新日是来源声明的时间；抓取时间证明本系统何时实际见到该版本。相同股票、报告期的内容发生变化时保留前后版本及各自首次观察时间，不用宽表 upsert 擦掉旧值。若接口只有最新快照，则它无法单独恢复此前各次修订的数值；首轮历史回抓即使带 `NOTICE_DATE`/`UPDATE_DATE`，也应标为“日期可追溯、完整修订史未证实”，不能自动判为完整历史 PIT。按同版本财务字段/哈希核对后，才可用独立披露日期补 QMT 的时间，不能只凭股票和报告期拼接不同版本。

发布前检查代码和日期、财报字段有限值、资产与负债基本关系、份额非负、字段单位、公告日不早于报告期、版本可用日不晚于发布时点。零净利润或负利润可合法存在；“所有核心字段均空”、不合理份额、缺失公告证据不得作为严格 PIT 发布。隔离记录保留原始证据与原因。股本采集失败不能记作整只股票财务数据已完整。

历史宽表指标只能在 `(stock_code, report_date, data_source)` 和 PIT 五个核心字段完全匹配时作为**待核对指标**回填。匹配不证明这些指标在 PIT 的原公告日已可见；除非 QMT 缓存中能核对同一版本的指标和披露/更新时间，否则其指标可用日起不得早于实际捕获日期。193 行未匹配 QMT PIT 逐项调查或重新取数，不用按键强行 JOIN。修订后的值产生新 PIT 版本，不原地改写旧版本。

## 历史时点读取规则

对研究日 `T`，先过滤报告期 `<=T`、有披露证据的版本可用日 `<=T`、质量合格的记录，再在同股票、同报告期内按版本可用日选择当时最新版本。现存 `source_table='trade_stock_financial'` 且 `announcement_date=report_date` 的 QMT 行，即使标为 `EXACT`，也须在读取层先阻断严格历史读取，待独立日期证据核实后再恢复；更改存量标记须保留备份和逐批审计。若同一历史时点 QMT 与 AKShare 均有合格版本，优先 QMT；QMT 缺失或不合格时选 AKShare。指标字段还必须满足自己的可用日期；暂存宽表指标不能借用财报核心字段的公告日。仅 `pit_estimated` 或日期来源不可靠的行不参与严格回测，明确放行的交互试算须带风险标记。

严格 PIT 读取器应传递来源和质量标记；TTM 必须先按报告期解析为唯一可见版本，再计算，防止同一期两来源重复计入四季。股本按独立公告日解析。当前 `DatabaseFinancialProvider` 不筛来源、`resolve_latest_visible` 仅按日期/哈希排序的行为需要更改，并补边界测试。

## 回补顺序、日常调度与验收

1. 固定当前三表快照和统计，建立 schema 扩展、暂存、批次台账与隔离表。先跑小样本（含同报告期双来源、修订、无公告日、负利润、股本变更）。
2. 本周桥接批量只读归档 QMT 2015 年起缓存，按股票和表分类审计；先补没有合格版本、缺失 EPS/ROE 等指标、193 个不匹配版本及股本缺口。QMT 缺失项用 AKShare 定向补。完成本周归档后，后续重跑可只依赖文件。
3. 发布已通过审计的 PIT/股本版本，并生成全市场按股票、报告期、来源、字段、日期类型的覆盖报告。未达标记录留在暂存/隔离，不能让总量数字掩盖缺口。
4. 在 PIT 数据稳定后，对受影响日期按历史时点重算 Repair Alpha/估值 `backfill` 快照；不把重新计算的结果标成当时真实 `live_shadow`。验收 API/Web 的修复候选、质量标志、估值字段及缺失提示。
5. 日常财务入口以 AKShare 的实际披露列表增量抓取；每次先保存原始响应、来源日期和首次观察时间，再比较内容哈希并发布新版本。每个披露日复查新公告及已跟踪报告期的修订，记录接口失败/空响应待重试清单。只有财务质量门和版本留存验收通过才接入正式每日入口。行情与非财务任务可以独立完成，财务失败明确返回非零并阻止财务衍生计算。

验收必须覆盖：2015 年起各年度/季度和上市时代分层覆盖；发布批次 0 个空核心行、0 个非法日期、0 个无证据 `EXACT`、0 个重复候选版本；同版本 EPS/ROE 等指标和来源数据一致；同一研究日不读未来公告/修订；AKShare 内容变化后旧版本仍可复现，历史快照的修订史不完整能被识别；QMT 优先及 AKShare 补位可复现；股本单位与市值样本合理；重跑幂等；桥接关闭后文件重放和 AKShare 日常均可运行。允许经审计的真实缺口，但必须逐项列明，不把覆盖不足报告为全量完成。

## 回退与边界

正式发布按批次事务执行，保留原始归档和旧 PIT 版本；读取策略通过配置/版本门切换，若验收失败可退回上一已验收批次。无需清空旧财务表。QMT 桥接只作为本周历史抓取手段，不能进入长期日常任务；其关闭日期以实际可用性为准。QMT 客户端文件的原生格式和公告字段须以下载完成后的真实样本验证；在此之前 JSONL 归档格式已能作为确定的离线导入接口。
